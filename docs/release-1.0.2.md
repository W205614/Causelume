# v1.0.2 发布检查

检查日期：2026-11-09，Asia/Shanghai。本版修复人工告警重投，并准备可独立获取的应用镜像；最终提交、CI、镜像摘要和发布后验收见 [v1.0.2 Release](https://github.com/W205614/Causelume/releases/tag/v1.0.2)。

## 修复与工程调整

- 同一服务、来源和外部事件 ID 的人工告警，在服务随后停用后仍返回首次接收的告警，不重复创建或改写原始观察。停用服务拒绝新事件。先用真实 HTTP 和 H2 复现 409，再调整现有服务行锁内的查询顺序；PostgreSQL 合同覆盖相同契约。
- 版本同步为 1.0.2，业务 schema 保持 V9，无依赖升级。目录仍按 frontend、backend、agent、deployment、scripts 分工，不新增架构层。
- app、agent 镜像加入项目许可、第三方说明、运行组件清单和精确对应源码入口。Agent 构建统一使用仓库根上下文，显式白名单仅提供所需源文件和许可材料；移除失去职责的旧 Agent 上下文忽略文件，并同步候选验收入口。
- 手动镜像工作流分成候选准备与同一制品推广。首次运行构建、走通离线 503→200 流程、扫描 HIGH/CRITICAL、收集精确对应源码并生成摘要，保存七天候选制品。维护者验收后，再用 `candidate_run_id` 推广原镜像，不重新构建；拒绝用不同内容替换既有提交标签。

## 分发与验收约定

分发目标为公开源码 Release，以及 `ghcr.io/w205614/causelume-app:<完整提交号>`、`ghcr.io/w205614/causelume-agent:<完整提交号>`；checkout 复用 agent 镜像。不可变身份以下载后核对的摘要为准。源码 ZIP、精确第三方源码 ZIP、镜像清单与 SHA256SUMS 随 Release 提供。原 v1.0.0/v1.0.1 源码发布保留。

镜像运行依赖的原始许可继续保留。对应源码采集器从实际候选提取 OS、Java、Python 的组件版本及来源，校验官方源索引中提供的摘要；缺少精确来源时阻止发布，不生成部分成功包。构建/采集入口与随附材料见 [第三方说明](../THIRD_PARTY_NOTICES.md) 和 [镜像源码说明](../deployment/licenses/SOURCES.md)。

本轮真实模型验收由用户单独授权：在独立临时数据库中发起一次调查，使用现有 gpt-6.1-sol 配置、合成故障证据、最多四步及每次输出上限 1200 token；日预算和单次预留各 1 美元。预留只控制平台准入，不是供应商扣费硬上限。只执行一次调查，不自动重试；供应商账单不明时保留 UNKNOWN。实际结果、用量与两项冻结工具证据在验收后写入 Release 和本地维护记录，不能用此前的离线或协议替身结果代替。

日常升级使用验收通过并实际拉取的同一镜像，保留现有业务卷、账号及配置。默认仍使用本机 offline 覆盖，不把一次隔离付费验收改成日常自动付费。升级前核对当前冷备与数据基线，升级后核对版本、健康、读取权限和数据兼容，最后恢复原停止状态。具体运行摘要及结果在升级后记录。

真实云主机、公开 TLS、供应商 SMTP、机外告警、异地恢复目标和实际生产容量仍属于外部接入验收；本轮不部署生产环境。

# 单机运维手册

本地 H2/checkout 演示使用 compose.yaml；Linux 单机部署使用 compose.production.yaml、compose.observability.yaml 和 PostgreSQL。配置操作见 [接入手册](production-setup.md)，隔离环境的集成测试见 [个人版验证记录](personal-release.md)。

根目录 `compose.yaml` 默认拉取固定版本标签的公开 app、agent 镜像，checkout 复用 agent 镜像；生产或升级可通过 `APP_IMAGE`、`AGENT_IMAGE` 固定目标 Release 的 `images.json` 中的不可变摘要。初始化、拉取与启动命令见 [快速开始](../README.md#快速开始)。需要验证源码改动时，显式合并 `compose.build.yaml`，见 [源码开发与测试](../README.md#源码开发与测试)。

## 适用场景

项目面向个人与企业内部小团队，采用单实例共享工作区。日常维护包括依赖更新、备份恢复演练、容量检查和模型费用核对。

| 使用范围 | 部署方式与准备事项 |
|---|---|
| 本地演示、开发和集成验证 | 使用 H2 与 checkout 示例，按 README 启动并运行示例流程 |
| 个人少量真实项目、可接受单机中断 | 使用 Linux 单机配置，接入项目数据源并完成下面的部署检查 |
| 企业内部小团队 | 成员共享服务、工单与证据；确认参与成员、数据可见范围和实际负载，验证记录见小团队交付文档 |
| 多团队、对外注册或高可用多实例 | 扩展项包括租户隔离、企业身份集成、多实例任务协调和高可用方案 |

## 部署检查

公网、SMTP、异地备份及机外探测接入后，逐项记录部署环境、版本与验证结果：

- [ ] 使用已通过对应 CI 的提交与固定镜像摘要，记录实际运行版本。
- [ ] 真实域名、TLS、MFA、Cookie、Origin 和内部端口隔离通过验证。
- [ ] 一个实际项目完成告警、邮件送达、工单、调查、恢复与复盘闭环。
- [ ] 从异地备份在干净环境恢复并核对数据，计时验证 RPO 24小时、RTO 2小时。
- [ ] 平台宕机、SMTP/数据源异常及备份停止均有可见状态或机外通知。
- [ ] 根据实际项目负载记录容量、磁盘增长和延迟，确定告警阈值及保留政策。
- [ ] 配置凭据轮换、备份恢复材料及维护责任；真实模型使用前明确隐私和费用边界。

| 主题 | 已实现能力 | 接入或扩展时的操作 |
|---|---|---|
| 数据与恢复 | PG18、独立迁移任务、运行进程无迁移凭据、H2离线核对迁移、一致加密备份、独立库恢复校验 | 接通异地仓库；完整新主机恢复并计时证明RPO24h/RTO2h。配置保留周期后再确认清理。 |
| TLS与代理 | Caddy HTTPS入口、内部端口隔离、Secure会话、固定Origin | 真实域名/证书/防火墙和代理链验收。 |
| 身份与凭据 | BCrypt、角色、会话撤销、强制TOTP、防重放及单次恢复码、受限文件 | 为部署准备专用密钥，轮换已公开或共享过的凭据；独立保管MFA加密密钥及恢复密码。按组织需求评估SSO。 |
| 告警与通知 | Alertmanager机器认证、标签/环境映射、过程去重、恢复、维护静默、事务Outbox、明确投递状态 | 配置真实SMTP与收件人，验证实际送达和服务商限额。 |
| 观测与隐私 | 服务范围、查询网关、同窗口快照、来源/缺失/截断记录、日志字段脱敏、受限导出 | 接入项目网络/日志卷并演练故障；设置供应商隐私与日志保留规则。审计与业务同库存储，防篡改归档作为独立接入项。 |
| 平台监控 | 请求/连接池/队列/失败/应用磁盘指标及规则、宿主磁盘阈值、机外运行与备份心跳入口 | 在机外创建检查并演练整机断联与备份停止；其他主机分区按需增加检查。 |
| 负载与限流 | 登录限流、请求和结果上限、稳定分页、单worker队列和查询边界 | 依据首批项目采集量实测CPU/内存/IO、延迟和磁盘增长，检查NAT限流误伤。 |
| 数据生命周期 | 服务停用保留历史、分页时间线、复盘/改进项、只读清理预览；观测存储7天保留 | 按保留与备份策略安排业务历史清理；当前业务历史由人工管理。 |
| 模型与工具 | 人工发起、冻结只读证据、结构化结果、每日预留、未知费用不自动重试或释放 | 配置专用密钥和预算，通过工单发起调查；按供应商账单核对实际费用，平台预留用于准入。 |
| 依赖与交付 | 固定基础镜像摘要、CI依赖/秘密/应用镜像扫描、发布清单、备份后升级 | 检查功能测试及安全扫描报告，处理漏洞并验证补丁与数据库回退。 |
| 扩容协调 | 单实例、单worker、条件终态与超时恢复 | 当前按单实例部署；扩展为多实例前增加任务认领、租约、恢复归属和共享配额。 |

H2演示升级先停止写入、复制静态库并验证副本。生产PG升级按发布脚本先备份；数据库停机或卷不匹配时，先恢复正确的数据库服务，再执行发布。数据库迁移后的回退使用经过核对的兼容应用版本或完整恢复集。历史数据清理按已确认的保留策略和备份状态执行。

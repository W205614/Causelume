# 验收边界

## 自动化覆盖

- 前端：Playwright 在独立模拟入口走查登录、导航、权限不足、空结果、建单、调查反馈、流转及复盘。真实浏览器测试使用临时 Java 数据库验证会话恢复、持久化复盘、审计、观察数据与调查证据。
- Java：嵌入式 HTTP 服务和 H2 验证迁移、服务端鉴权、跨站写入、重复告警和工单、同版本并发写入、工单流转与时间线。任务测试将外部推理服务隔离为本地 HTTP 服务，验证任务状态、上游超时、幂等与反馈权限。
- Python：使用真实本地 checkout HTTP 读数，验证正常与故障样本、恢复、读写权限分离、缺少证据、上游错误、超时及工具白名单。模型协议测试使用受控响应。
- 全栈：scripts/verify_local.py 启动真实 Java、调查进程、示例服务和 Chromium。scripts/e2e.py 触发可观测的 503，从告警走到工单关闭，并在恢复步骤实测 HTTP 200。覆盖浏览器显示已持久化的指标、日志证据和人工反馈。CI 中模型模式固定为 offline。
- 本机 Docker：按根 README 部署后，用同一业务脚本核对容器网络和持久化业务数据。真实模型的联网调用与离线检查分开记录。

## 数据范围

样例服务以信号量模拟容量为 1 的连接池，受控占用产生真实失败，指标和请求日志在内存保留最近 50 条。工单、审计、快照证据和复盘存入 H2 文件。单次真实模型验收只说明当时的连接、工具和输出契约是否可用，不构成生产诊断准确率或可靠性评测。

迁移测试和本地启动均实际执行 Flyway V1/V2。Boot 管理的 H2 2.4.240 高于该 Flyway 声明已验证的 2.3.232；变更任一依赖时需重跑文件库迁移和端到端检查。
